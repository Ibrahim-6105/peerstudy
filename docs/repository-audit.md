# Repository Audit

Last audited: 2026-06-25

## Summary

The folder is a clean Flutter starter project. It has platform runners for
Android, iOS, web, Windows, Linux, and macOS, plus a default widget test. The code
currently implements the generated Flutter counter app rather than the PeerStudy
product described in the project document.

## Current Project State

- Git repository: initialized locally on branch `main`.
- App entry point: `lib/main.dart`.
- Current UI: default Flutter counter scaffold.
- Current test coverage: default counter smoke test in `test/widget_test.dart`.
- Current dependencies: Flutter SDK, `cupertino_icons`, `flutter_test`, and
  `flutter_lints`.
- Ignored generated folders: `.dart_tool/`, build output, coverage, IDE files,
  and platform build artifacts.
- CI: Flutter quality workflow added under `.github/workflows/`.

## Verified Commands

These commands were run successfully:

```powershell
flutter pub get

flutter test
```

Results:

- Dependency resolution completed successfully.
- Static analysis reported no issues.
- Widget smoke test passed.

## Folder Analysis

### `lib/`

Contains the current Flutter application code. The file is still the generated
starter app and should be replaced with a product-oriented structure before the
PeerStudy MVP is developed.

Recommended future structure:

```text
lib/
  app/
  core/
  features/
    auth/
    academic_path/
    lectures/
    quizzes/
    community/
    moderation/
  shared/
```

### `test/`

Contains one starter widget test. It verifies the counter behavior and should be
replaced or expanded as product screens are implemented.

Recommended next tests:

- Authentication validation tests.
- Academic path routing tests.
- Concept page rendering tests.
- Report workflow tests.
- Firestore repository tests with mocks or emulator support.

### Platform Folders

The platform folders were generated by Flutter and should remain mostly
framework-managed:

- `android/`
- `ios/`
- `web/`
- `windows/`
- `linux/`
- `macos/`

Changes inside these folders should be limited to platform configuration,
permissions, Firebase setup, icons, app names, and deployment settings.

### `.github/`

The folder existed but did not contain usable workflow files. A Flutter quality
workflow has now been added.

## Risks and Gaps

- Product features from the SRS are not implemented yet.
- Firebase has not been configured.
- No environment or secrets strategy exists yet.
- No data model has been implemented.
- No role-based access model exists yet.
- PDF viewing, media upload, and AI quiz packages have not been selected.
- The project document has a persistence ambiguity: local SQLite is mentioned for
  caching, while MySQL is also mentioned as part of the software interface.
- The current test still validates starter behavior, not PeerStudy behavior.

## Immediate Recommendations

1. Replace the starter app with a small authenticated app shell.
2. Add Firebase configuration for supported target platforms.
3. Define Firestore collections and security rules before building community
   features.
4. Add a feature folder structure before the codebase grows.
5. Implement university email validation as a reusable domain rule.
6. Add automated tests alongside each feature.
7. Decide whether offline support means local SQLite, lightweight file cache, or
   Firestore persistence only.
